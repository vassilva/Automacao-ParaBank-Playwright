## How REQ-27 behaves

GitHub deletes the **head branch of a pull request when that pull request is merged**, and only
then: a branch whose pull request is still open, or was closed without merging, is never touched
(an open PR's branch cannot be deleted by its own merge before that merge happens). Not deleted
either: the default branch (`main`), branches protected by a ruleset or branch protection, local
branches, and existing branches (no retroactive deletion). The pull request, its commits, reviews
and checks remain, and a deleted head branch can be restored from the pull request page. This
repository does not stack pull requests on feature branches, so no behavior for stacked pull
requests is relied on. Jenkins then removes that branch's job on its next scan.
